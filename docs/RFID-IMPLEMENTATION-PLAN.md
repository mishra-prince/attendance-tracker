# Main RFID attendance implementation

23 October 2026. User confirmed ESP32-S3 + MFRC522/RC522 and one alternating entry/exit reader.

The existing central User, Student, Section, Enrollment, Timetable, ClassSession and Attendance models already implement the v2 architecture. Preserve them and the percentage service. Add RFID reader credentials/capture state, card assignments, immutable tap events and visit intervals; add RFID attendance method and an optional session room snapshot. Existing data is preserved by an additive migration; backfill existing session rooms only. No historical student deletion or bulk rewriting of attendance.

Use the current JWT/refresh-session account authentication for admin/staff/student APIs. Device taps use separate revocable per-reader random credentials (hash stored server-side) over verified HTTPS. No student/session/direction is accepted from firmware. Server time, room, timetable, active student/card/enrollment and session state determine the result. Lock the reader and student in a transaction, deduplicate event IDs and debounce repeated scans. Record physical entry/exit timestamps and preserve staff attendance decisions. Do not invent a missing checkout. Card UID is a clonable bearer identifier; this feature does not establish live student identity or replace face verification.

Admin registration creates the User, Student and section subject enrollments atomically. Section rosters feed teacher class views automatically. Existing/bulk registration uses the same helper; new timetable/subject assignment synchronizes missing enrollments without reactivating intentionally dropped enrollments. Removing a student deactivates account/access/cards and retains history; resetting a card revokes the old assignment before a supervised scan/replacement. Device key rotation/revocation, enrollment capture, cards, taps, attendance and removals are audited transactionally.

Add /api/rfid device tap, admin readers/capture/cards/student lifecycle, and scoped daily class/roster views. Tighten existing session/roster reads used by the UI to assigned teacher / HOD department / admin and self student access. Add main app RFID attendance and admin cards/readers pages plus today's classes/in-out on the student attendance page. Keep original BLE/manual/QR/face demo entry points and app signing/package; this RFID feature uses authenticated main routes, never demo evidence.

Build an ESP32-S3 sketch with custom SPI pins SCK12/MISO13/MOSI11/SS10/RST9, 3.3V RC522 supply, Wi-Fi, NTP, certificate-verified HTTPS, per-reader provisioned credentials, event retry identity and physical card removal gating. Provide wiring, library/compiler record, provisioning and backup-first flashing instructions. No serial write access or live deployment is assumed. Compile and run API/database/RBAC/replay/revocation/migration tests, frontend build and Android checks. Publish sources and the same-package APK after checks. Physical tap/TLS/live server deployment require separate evidence and are reported honestly.
